# Изменения

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии и выпуск — [docs/releasing.md](docs/releasing.md). Каждый PR библиотеки, включая документацию, тесты и CI, добавляет строку в «Unreleased»; исключение — полностью ботские PR Renovate только с зависимостями, их сводку по `go.mod` добавляет PR выпуска. При выпуске раздел получает номер версии и дату.

## [Unreleased]

- FIN-372: CI и конфигурации линтеров получают общий источник по неизменяемому SHA; локальные команды используют тот же профиль, обновление и откат выполняются одним PR. Runtime и публичный API не меняются.

## [v0.6.0] — 2026-10-26

### Исправлено


- FIN-225: replay использует один момент Clock после блокировки строки для решения о сроке и пересчёта деталей, включая Reserve/DoReserved; пересечение expires_at во время декодирования больше не превращает уже разрешённый replay в ложный ErrStorage.
- FIN-225: replay сохранённых ошибок сохраняет полный проверенный gRPC Status и неизвестные Any; RetryInfo обновляется от абсолютного срока и переданного Clock без потери RequestRetryInfo, metadata или validation details. Положительное разрешение ограничено фактическим сроком записи; отсутствующее/false не повышается. Новые необязательные ожидания получают private абсолютный anchor, старые без anchor не запускаются заново. Противоречивые сроки/детали закрываются ErrStorage. contracts/gen/go обновлён до опубликованного v0.5.0; публичный API, SQL и политика TTL не меняются.

### Несовместимо

- FIN-225: семантика replay ошибок стала строже: старый optional RetryInfo без абсолютного anchor удаляется, прежний RequestRetryInfo=true ограничивается до false при неизвестном времени или отсутствии окна до expires_at; известное прошедшее ожидание снимается. Некорректный сохранённый Status/binding даёт ErrStorage без повторного эффекта. Сервис должен допускать отсутствие RetryInfo у optional ошибок и явный false, не выводить permission из reason, сохранять обработку ErrStorage и закрепить опубликованный владельцем новый тег перед использованием этого поведения. SQL и публичный Go API не меняются; обновление consumers и rollout выполняются отдельно.

### Изменено

- Обновления Renovate после v0.5.0: go-migrate v0.1.1 → v0.2.0 и go-outbox v0.1.0 → v0.2.0. Повышение contracts/gen/go до v0.5.0 описано в FIN-225 выше; остальные зависимости и минимальная версия Go не менялись.
- FIN-225: восстановлен раздел уже опубликованного v0.5.0 по CHANGELOG из его неизменного коммита; прежний тег и модуль не меняются.

## [v0.5.0] — 2026-10-26

### Несовместимо

- FIN-296: `Response.Headers` принимает только значения из печатного ASCII `0x20–0x7E` и ключи без суффикса `-bin`; иначе `ErrInvalidRequest` и откат эффекта. Раньше такой исход коммитился, но `grpc.SetHeader` отказывал при каждой отправке (INTERNAL на 24 ч), а бинарные значения искажались при replay. Непустой scope не в формате UUID теперь даёт в интерцепторе `INTERNAL_ERROR` вместо `VALIDATION_ERROR` по `idempotency-key`. Исход, сохранённый до обновления с ключом `-bin` или значением вне `0x20–0x7E`, при replay до своего `expires_at` даёт `ErrStorage` (сервис отвечает `INTERNAL_ERROR` вместо сохранённого ответа), эффект не повторяется — отказ закрытый. user и assistant заголовков не сохраняют и передают проверенный UUID — правок не требуется; bank-statement-data библиотеку пока не подключает и не затронут. Бинарные данные сервис переносит в тело ответа.

### Добавлено

- FIN-297: `Engine.StreamInterceptor(scope)` — извлечение `idempotency-key` для потоковых RPC (client-streaming `UploadStatement`) по тем же правилам, что `UnaryInterceptor`; `FromContext(stream.Context())` возвращает `Request`. `HashUpload(contentHash, fileName)` — хеш запроса `UploadStatement` по формуле контракта (grpc-api.md, раздел 6): `SHA-256(SHA-256(содержимое) ‖ file_name)`, имя без нормализации. README («Внедрение», разделы 2, 4, 7) описывает порядок: ключ при открытии потока, хеш и `Do` после последнего `chunk`, `FILE_TOO_LARGE` без сохранения. Тесты используют сгенерированный `StatementsService` из `contracts/gen/go` v0.4.0, поэтому в `go.mod` появилась indirect-зависимость protovalidate той же версии, что у contracts; минимальные версии Go и contracts не повышены. Поведение существующих API не изменилось.
- FIN-244: пример и consumer-тесты композиции с опубликованным go-postgres v0.1.2, Publisher outbox и tombstone Guard: общий COMMIT, replay, вложенный Run, полный откат при callback/deferred FK, чужой Manager, отмена/panic/Goexit. Guard пользовательского scope проверяется до чтения ключа, Purge атомарно удаляет outcomes по scope/owner. Production API и интерфейс Tx не изменены; новые зависимости используются только тестами и примерами.
### Изменено

- FIN-341: правила lint о процессном состоянии приведены к ядру go-library-template (FIN-322): секции `forbidigo` и `depguard` в `.golangci.yml` и `scripts/test_lint_policy.py` совпадают с шаблоном. Добавлены запреты `slog.With` и `os.Exit`; сняты правила вне ядра: `grpclog` и `grpclog/glogger`, `prometheus.Unregister`, `http.DefaultTransport`/`DefaultServeMux`/`PostForm`, `otel.Tracer`/`Meter`/`Handle` и `otel/log/global`, `os.UserHomeDir`/`UserConfigDir`/`UserCacheDir`, `os.TempDir`/`CreateTemp`/`MkdirTemp`, `(*os.File).Chdir`, `runtime.SetDefaultGOMAXPROCS`, `syscall`/`golang.org/x/sys`; принцип в целом проверяется на ревью. Runtime и экспортируемый API не менялись.
- FIN-308: перенесены из go-library-template запреты `forbidigo` и `depguard` на глобальное состояние (FIN-294) со `scripts/test_lint_policy.py` и защита CI (FIN-301): `persist-credentials: false` у checkout в `lint`, `api`, `migrations`, `github.base_ref` через `env`, `scripts/test_workflow_hardening.py`. Проба `test_lint_policy.py` берёт для каждого модуля из `go.mod` большую из версий `go.mod` и ручной (после `go mod tidy` — точное совпадение), иначе ручную версию как минимальную (по semver не ниже): иначе после PR Renovate проба проверяла бы запреты на старых grpc/prometheus или падала бы, когда новый otel поднимает otel/log (otel v1.47 требует otel/log v1.47). Нарушений в production-коде не найдено; runtime и экспортируемый API не менялись.
- FIN-309: `docs/releasing.md` и вступление CHANGELOG по FIN-307: строка в `[Unreleased]` от каждого PR, включая документацию, тесты и CI; заголовок PR выпуска с ключом FIN; бот-PR Renovate без строки, их сводку по `go.mod` вносит PR выпуска. Runtime и API не менялись.
- FIN-317: `internal/pgtest` больше не копирует go-migrate (по FIN-310): оставлен только выбор тестового PostgreSQL (`TEST_DATABASE_URL`/testcontainers, skip локально, ошибка в CI), создание БД, правила файлов и обход up → down → up делегированы `github.com/fin-assist/go-migrate` v0.1.1. go-migrate импортируется только тестами, но как require модуля входит в граф модулей и повышает минимальную версию go-migrate у сервисов, импортирующих библиотеку (сервисы уже на v0.1.1). Исключение `internal/pgtest` из покрытия не изменилось; runtime и экспортируемый API не менялись.
- FIN-243: независимые unit/integration/API statements gates 80 % production-пакетов (по согласованию исключён только internal/pgtest), защита от пустых suite и содержательные тесты публичного API; прежний coverage-diff удалён. Runtime и экспортируемый API не изменены.

## [v0.4.0] — 2026-10-24

Сервис применяет миграции до обновления и сериализует purge с выполнением/replay.
