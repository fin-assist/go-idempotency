# Изменения

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии и выпуск — [docs/releasing.md](docs/releasing.md). Каждый PR, который меняет API или поведение библиотеки, добавляет строку в «Unreleased»; при выпуске раздел получает номер версии и дату.

## [Unreleased]

### Несовместимо

- FIN-296: `Response.Headers` принимает только значения из печатного ASCII `0x20–0x7E` и ключи без суффикса `-bin`; иначе `ErrInvalidRequest` и откат эффекта. Раньше такой исход коммитился, но `grpc.SetHeader` отказывал при каждой отправке (INTERNAL на 24 ч), а бинарные значения искажались при replay. Непустой scope не в формате UUID теперь даёт в интерцепторе `INTERNAL_ERROR` вместо `VALIDATION_ERROR` по `idempotency-key`. user и assistant заголовков не сохраняют и передают проверенный UUID — правок не требуется; бинарные данные сервис переносит в тело ответа.

### Добавлено

- FIN-244: пример и consumer-тесты композиции с опубликованным go-postgres v0.1.2, Publisher outbox и tombstone Guard: общий COMMIT, replay, вложенный Run, полный откат при callback/deferred FK, чужой Manager, отмена/panic/Goexit. Guard пользовательского scope проверяется до чтения ключа, Purge атомарно удаляет outcomes по scope/owner. Production API и интерфейс Tx не изменены; новые зависимости используются только тестами и примерами.
### Изменено

- FIN-243: независимые unit/integration/API statements gates 80 % production-пакетов (по согласованию исключён только internal/pgtest), защита от пустых suite и содержательные тесты публичного API; прежний coverage-diff удалён. Runtime и экспортируемый API не изменены.

## [v0.4.1] — 2026-10-24

### Исправлено

- FIN-227: восстановлено распределение изменений по выпущенным версиям v0.1.0–v0.4.0 и описан порядок восстановления оформления выпуска. API, поведение и миграции не менялись.

## [v0.4.0] — 2026-10-24

### Добавлено

- FIN-230: необязательная Response.Resource (тип и внутренний ID), атомарная связь успешных/сохраняемых ошибочных ответов с ресурсом и проверка при replay. BindResource связывает только собственный действующий резерв и передаёт связь в DoReserved. Миграции 004/005 добавляют nullable-столбцы и CONCURRENTLY-индекс для адресной очистки; старые исходы читаются, scope/OwnerID/TTL не меняются. Сервис применяет миграции до обновления и сериализует purge с выполнением/replay.

## [v0.3.0] — 2026-10-23

### Добавлено

- FIN-229: ReleaseIfCurrent возвращает факт освобождения своей действующей резервации для атомарной компенсации лимитов в транзакции сервиса; срок проверяется после ожидания блокировки. Старый Release и существующие вызовы совместимы; новых миграций нет.

## [v0.2.0] — 2026-10-23

### Добавлено

- FIN-226: необязательный Response.OwnerID, атомарное хранение владельца результата без изменения scope, возврат при replay и проверка связи с payload; миграции 002/003 с nullable owner_id и CONCURRENTLY-индексом для адресного удаления. Старые ответы без владельца читаются как прежде; сервис применяет миграции перед запуском и проверяет tombstone владельца auth-replay.

## [v0.1.0] — 2026-10-23

### Добавлено

- FIN-78: транзакционная идемпотентность с идентификаторами операций для gRPC и HTTP, gRPC metadata, хеширование запросов, резерв 15 с с fencing, AES-GCM для refresh, очистка и метрики; инструкция внедрения и проверки на PostgreSQL 18 и gRPC.

### Исправлено

- FIN-78: ожидание занятого ключа в Do и DoReserved ограничено также EffectTimeout; отмена клиента после начала эффекта по-прежнему не прерывает его фиксацию.
