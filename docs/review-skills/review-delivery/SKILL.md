# review-delivery

1. Проследи фактический путь исполнения: событие → workflow из нужной ветки → checkout/источник инструкций → разрешённые инструменты → результат. Файл на компьютере автора не доказывает доступность в GitHub. Различай проверенную конфигурацию и наблюдённый запуск.
2. Сравни permissions, secrets, fork/actor gates, pinned dependencies и публикации с базой PR. Инструкции и тесты не дают новых прав. Не выполняй код PR с привилегиями ревьюера ради проверки документации.
3. Для новых инструкций прочитай ссылки из чистого checkout: относительные пути, материал нужной ревизии, отсутствие локальных абсолютных путей. Проверь основной выбор, отсутствие подходящего навыка, недоступный файл и несколько областей; fallback должен сохранять обязательные проверки.
4. Проверь происхождение и право распространения каждого заимствованного материала до копирования. Для оригинального проектного текста зафиксируй происхождение; не добавляй сторонний каталог целиком. Определи владельца/способ обновления и каждый действующий потребитель, не считай их обновлёнными вслед за шаблоном.
5. В результате назови прочитанный файл, применённую процедуру и конкретное наблюдение. Список названий и реакция одобрения не доказывают чтение. Новые права, автоматизация, инфраструктура или обязательные тестовые прогоны требуют существующего основания в задаче.

Результат — проверяемые наблюдения в рамках Code Review Rules. Сам навык не разрешает внешние действия.
