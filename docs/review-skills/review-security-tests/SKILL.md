# review-security-tests

1. Для затронутой области отметь недоверенный ввод, подтверждённую идентичность, владельца объекта и побочный эффект. Пройди каждый переход: чужой пользователь, чужой caller, удалённая учётная запись, отказ согласия, враждебный файл/ответ.
2. Проверь, что секреты и финансовые данные не попадают в логи/ошибки/метрики; параметры SQL, лимиты работы и таймауты не обходятся. Для финансовых изменений сверь единицы/знак/валюту, границы дат, дедупликацию, собственные переводы и возвраты с контрактом.
3. Сопоставь основной путь, альтернативы, достижимые ошибки, границы и повторы с конкретными тестами. Для конкурентных гарантий нужны реальные конкурирующие операции; для SQL — настоящая БД. Процент строк и прохождение фейка не доказывают сценарий.
4. Для каждого утверждения различай: прочитан тест; тест реально выполнен; проверено только статически. Не запускай UI/деплой/публикацию и не получай секреты в рамках этого навыка. Тесты выполняются только в пределах разрешений и с прерывающим процесс таймаутом.
5. Для изменения инструкций проверь, что обязательные security/test требования остаются в AGENTS.md и действуют даже без этого файла. Укажи недоступные проверки и остаточную неопределённость; замечания привязывай к достижимому сценарию.

Результат — проверяемые наблюдения в рамках Code Review Rules. Сам навык не разрешает внешние действия.
